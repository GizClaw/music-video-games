# @gizclaw/mvg-games

The complete music universe and its rhythm games, ready to mount in a host page. The SDK includes the opening stage, galaxy and planet catalog, 3D scenes, music crossfades, Chinese/English interface, styles and game loaders. GitHub Pages uses this same SDK entry. Install the tarball from a GitHub Release together with `@gizclaw/mvg-core`. Deploy handles subsequent publication to the TOS npm registry. Use a bundler such as Vite to resolve the npm imports, packaged JSON and `?raw` assets.

```sh
# Set this to an actual UTC snapshot tag from the Releases page.
release_tag=vYYYYMMDD-HHMMSS
npm install \
  "https://github.com/GizClaw/music-video-games/releases/download/${release_tag}/gizclaw-mvg-core-0.1.0.tgz" \
  "https://github.com/GizClaw/music-video-games/releases/download/${release_tag}/gizclaw-mvg-games-0.7.0.tgz"
```

## Complete game entrance

```html
<div id="games" style="height: 100vh"></div>
<script type="module">
  import { mountUniverse } from "@gizclaw/mvg-games/universe.js";
  const games = mountUniverse("#games");

  // games.open("stem-institute");
  // games.play("binary-boogie", { start: 31, auto: true });
  // games.destroy(); // call when the host view unmounts
</script>
```

`mountUniverse` and the default `SERIES` catalog are also exported from `@gizclaw/mvg-games`. The `universe.js` entry loads individual games on demand. Give the target a height; the universe fills that container and installs its styles automatically. No files from the repository's `site/` directory are needed. Music streams from the catalog CDN, as it does in the individual games.

Options:

| Option | Default | Behavior |
| --- | --- | --- |
| `series` | `SERIES` | Replace the bundled galaxies and works, or pass a subset of `SERIES`. |
| `lang` | Saved choice, then `"zh"` | Initial interface language (`"zh"` or `"en"`). |
| `routing` | `true` | Use `#/<series>/<work>/play` routes and browser back. Set `false` when the host owns the URL. |
| `manageDocument` | `false` | Update the document title and language. The Pages host enables this. |

`open(id)` flies to a galaxy or selects a song; `play(id, { start, auto, play })` opens a playable song. Song ids may be qualified as `<series>/<work>`. Universe navigation keys work while focus is inside the container; clicking it focuses the container. A full-page host can give the target `tabindex="0" autofocus`, as the Pages host does. `destroy()` stops the hub's animation and music, disposes its scene, removes listeners and mounted games, and restores the container's original attributes. Without WebGL the hub displays the catalog; `open` and `play` report that WebGL is unavailable.

The catalog source is `src/universe/universe.json`; `npm run universe:catalog` in the repository regenerates it. Planet looks and game loaders live in `src/universe/catalog.js`.

## Individual games

```html
<div id="game" style="height: 100vh"></div>
<script type="module">
  import { mountSpectrumSlide } from "@gizclaw/mvg-games";
  mountSpectrumSlide("#game");
</script>
```

`mountSpectrumSlide`, `mountPlanetParade`, `mountBinaryBoogie`, `mountPrimeTime`, `mountPenguinSteps`, `mountStatesOfMatter`, `mountPolygonParty` and `mountFrogHopStop` fill the element with the canvas, chart and HUD. Pass `audio`, `start`, `play`, `auto`, or `backHref` when the host is not using the page query string. Every game speaks Chinese and English: `lang: "zh"` or `"en"` picks one, otherwise the universe hub's saved choice (`mvg-universe-lang` in local storage) is used, falling back to Chinese; the hub passes its current language when it mounts a game. Lyrics stay in the song's own language. Shared pieces (audio clock, glow sprite, post shader, catalog audio URL) stay at `@gizclaw/mvg-games/kit.js`. `@gizclaw/mvg-games/sfx.js` synthesises the interface and game sounds with WebAudio (no files): call `sfx.unlock()` in a user gesture, then `hover`, `click`, `select`, `slide`, `enter`, `back`, `warp`, `gate`, `hit`, `chip`, `laser`, `boom`, `stomp`, `wrong`, `miss`, `collect`, `press`, `stamp` and friends. Pitched sounds climb a C major pentatonic, and the site-wide mute (`mvg-universe-muted` in local storage) silences them. Both games and the universe hub use the shared `sfx` instance; the games stay silent in their title-screen demo.

Phones: `@gizclaw/mvg-games/mobile.js` keeps play from turning into page gestures (`lockGestures` blocks long-press menus, pinch and double-tap zoom, pull-to-refresh and edge swipes), turns the back button into a pause (`backGuard` pushes a same-URL history entry while playing; a second back leaves), keeps the screen awake while a song plays (`wakeLock`), and on touch screens starts fullscreen and asks for landscape (`goFullscreen`) and buzzes on hits (`buzz`). Both games use them; the universe hub locks gestures and, when it pushed the game route itself, leaves a game by stepping back over the guard entry so no stale game route is left in history. On touch screens (or with `?simple`) Planet Parade plays as a one-button game: rings close on a big tap button, a tap anywhere hits the next open note whatever its planet (so planets are still collected), tapping more than a window early breaks the combo, and the planet tags and key lane are hidden. It shows only planet numbers on small screens, and on a tall screen raises the camera and marches the planets in two rows (1–4 behind the Sun, 5–8 in front).

## Clearing, failing and results

Every game can be cleared and can be lost, and both end on the same result screen (`src/finale.js`). A life gauge sits under the score: misses and wrong presses drain it, hits refill it a little (`LIFE` holds the shared amounts; each game tunes its own). Playing to the end of the song clears the stage; Binary Boogie and Prime Time loop, so they clear after 2 rounds, the second faster. When the gauge empties the run fails at once: the stage turns grey, the song winds down like a stopped tape and a red FAILED stamp shakes in. A clear gets a gold CLEAR! stamp and the music plays on. Then the result overlay shows the verdict (STAGE CLEAR or FAILED), the grade, the score, the game's stats (a failed run's first row is how far it got) and the best score, kept in local storage under `<game>-game-best` for manual runs from the start of the song. The grade comes from weighted accuracy: S 95%, A 85%, B 70%, C 50%, otherwise D; a failed run is F whatever its accuracy. `sfx.clear()` and `sfx.fail()` play the two endings.

## Slide Down the Spectrum

The chart is built in the package from `src/spectrum/analysis.json` (beats, onsets, aligned lyrics). `mvg-video --work spectrum-slide game-data` still writes `aigc/songs/music/stem-institute/en-us/spectrum-slide/game/analysis.json`, which is a link to that file. Notes run every other beat from 4 s to the drop, then every beat, with half-beat notes on strong off-beat onsets in choruses, the bridge and the outro. Note angles follow seeded per-bar motifs capped by how far the photon can turn before the next note; γ gates (a full ring with one opening) land on chart downbeats in the dense sections. The song clock is `audio.currentTime` smoothed against `performance.now()`, with a player-adjustable offset (`[` and `]`) kept in local storage. `?start=SECONDS` begins mid-song, `?play` starts without the title card and `?auto` steers automatically for screenshots.

## Planet Parade

A roll call: the chart is built from `src/planet/analysis.json`, linked from `aigc/songs/music/stem-institute/en-us/planet-parade/game/analysis.json` the same way. The planets circle the Sun on faint orbits in their own colours (an orbit lights up while a ring closes on its planet) and step out into a line for the lineup, both choruses and the finale (`PARADES` in `src/planet/song.js`). A note is a ring closing on a planet, Pluto or the Sun; hit it by clicking the body or pressing its number (`1`–`8` for Mercury to Neptune, `9` for Pluto, Space or `0` for the Sun). Every sung planet name is a note on that planet, "Pluto" a note on Pluto, and sun, march, hey, hooray and eight are notes on the Sun; all snap to the half-beat grid, pushed half a beat on when two land together. Filler notes keep the beat (every beat in the lineup, choruses and finale, every other beat in the verses and bridge): in a line about one planet they repeat it, elsewhere they march through the planets in order, and in the bridge they fall on the Sun. A key lane above the lyrics slides the next 2.4 s of keys into a NOW box, and the due planet's tag grows into a key cap. Hitting the wrong body while a note is open breaks the combo. `?start`, `?play` and `?auto` behave as in Slide Down the Spectrum; the offset key is `planet-game-offset`.

## Binary Boogie

An endless binary blaster paced for people. Four switches are the 8, 4, 2 and 1 bits (keys `A S D F` or the on-screen switches; Space or the red switch clears them to 0, and they clear themselves a moment after each shot), and the cannon stands on a 0–15 number line at the value they spell. One pixel invader at a time carries a number and hangs over its place on the line: it appears on a beat and marches down one step per beat, and the beat after the switches spell its number it is shot; if it reaches the line first it gets through. The next appears two beats after the last is shot or gets through, skipping a number the switches already spell.

Until three seconds before the first chorus the invaders are lessons: they come down over 16 beats and then wait on the line for ever, the first eight (1, 2, 3, 8, 4, 5, 6, 7) carry a tip above the switches, the switches that still need flipping blink and the answer shows under the invader; drills without tips follow. After that an invader takes 20 beats to reach the line, one beat fewer for every 24 beats of play down to 4; its bits show under it halfway down, and it flashes red for its last 2 beats. Each invader that gets through costs one of three lives, shown as a three-cell life gauge (a boss gives one back, up to three); the run fails when they run out. On the last whole bar before the song's end it jumps back to the first chorus and the second round begins, with verse 2, the bridge and the bosses replaying; reaching that bar again clears the stage. Choruses and the outro walk 0 to 15 in Gray code (one flip each) with a 15 boss when a chorus's "boogie" falls during the march; verse 2 counts 8 to 15; the bridge clears to 0 and lights 8, 12, 14, 15, then 11. Every invader shot lights its number in the 0–15 strip. Beats are counted across passes so invaders and timers carry over the jump. `?start`, `?play` and `?auto` behave as in the other games, and the offset key is `binary-game-offset`.

## Prime Time

Whack-a-prime on the 1–100 board from the music video, charted from `src/prime/analysis.json` (linked from `aigc/songs/music/stem-institute/en-us/prime-time/game/analysis.json`). Only primes pop up, each on a beat; click or tap one while it is up to knock it down and light it gold (Space, `J`, `F`, `K` or `D` knock down the earliest one instead). From the beat after it pops, the tile breathes with the music: on every beat it flashes its brightest, its halo swells and a ring goes out from it. That is its best moment: a hit within 90 ms of one of those beats is PERFECT, within 180 ms GREAT, any other time while it is up GOOD, and a prime that sinks back unhit is a miss. Non-primes never pop up: on their beat their multiplication (`3×7`) rises off the tile and crosses it out. Each chorus's two "Check the line!" sieve on the beat of "line": every multiple of 2 and 3 (chorus 1), 5 and 7 (chorus 2), or 2 and 3 then 5 and 7 (chorus 3) pops and is crossed out in a cascade.

Every number the song sings is a note on the beat nearest its word ("one hundred" is 100; at most two to a beat, a third moves on to the next). Fillers take the beats nobody sings on: every beat in the choruses, bridge and outro, every 2 beats in the intro and verses of the first pass and every beat after, never a number sung within 4 beats. The intro's fillers take turns between primes and non-primes (2, 4, 3, 9, 5, 6, …); after that they are half primes and half non-primes from the section's range. On touch screens the board fills the screen (the score, power, lyric and prime count move to its sides in landscape) and a tile that is up pops out toward the player at about 2.4 times its size, leaning in from the board's edge, so it is big enough for a finger. A tap is matched against where the up tiles are drawn: it counts for the nearest one within 1.25 of its drawn half-widths (1.6 on touch screens), and a tap with nothing up still flashes its tile and ticks.

Until the first chorus the tiles are practice: primes stay up for 5 beats, a tip shows under the board, and nothing drains. After that a missed prime drains the life gauge and hits refill it a little; lighting all 25 primes (the bridge sings every one) refills a large share, and the run fails when it empties. The song loops from the first chorus like Binary Boogie's with a fresh board, and the second round's end clears the stage; notes are kept in game time (song time plus the passes before), the next pass is charted a pass ahead, and primes stay up for 3 beats on the first pass and 0.4 beat less each pass down to 1.5. `?start`, `?play` and `?auto` behave as in the other games, and the offset key is `prime-game-offset`.

## Frog Hop Stop

A three-button lily-pad dance on the sunset pond from the music video, charted from `src/frog/analysis.json` (linked from `aigc/songs/music/animal-dance-en/en-us/frog-hop-stop/game/analysis.json`) with the video's word-time fixes. The stage is a row of three lily pads with the frog facing the camera; notes fall down three lanes onto three round buttons (left, middle and right: the arrow keys `←` `↑` `→`, with Space and `↓` also the middle, or `A` `W`/`S` `D`; on phones, the three buttons), and a hit hops the frog onto that lane's pad. Ribbits and the spring words alternate left and right, "hey, hey, hey" runs left, middle, right, "Hop!", push and leap are big golden middle notes, "one" and "two" are left then right, and each "hooray" is a big left-and-right chord that jumps the frog up with its arms raised. Every chorus's "Bend down low, then gently stop!" is a purple middle hold: press on "Bend" (the frog crouches), keep holding, and let go on "stop" to freeze. Notes snap to the half-beat grid and keep at least 0.3 s apart. Fillers keep the beat where nothing is sung within three quarters of a beat: every beat in the choruses (left, middle, right, middle), every other beat elsewhere (left, right).

A press or release within 70 ms is PERFECT, 120 ms GREAT and 180 ms GOOD; pressing a button while only other lanes are due breaks the combo, and pressing when nothing is due is free. A missed note splashes the frog into the water by its pad and it climbs back out, and letting go of a hold too soon or too late misses its stop. On wide screens three frogs dance along with the lead from the start, in two rows behind the stage, mirroring each hop, and every ten hits another joins, up to eight; phones show the lead alone. From "freeze" to "Breathe" nothing falls and any press counts as moving (holding still is worth 1000 points), and the slow breathing that follows is a rest. The sky turns from sunset to firefly night as in the video. The song plays once and ends with a grade. `?start`, `?play` and `?auto` behave as in the other games, and the offset key is `frog-game-offset`.

## Penguin Step Party

A four-pad dance game on the ice floe from the music video, charted from `src/penguin/analysis.json` (linked from `aigc/songs/music/animal-dance-en/en-us/penguin-steps/game/analysis.json`) with the video's word-time fixes. Notes fall down four lanes onto a row of pads: left foot, flipper, clap and right foot (the arrow keys `←` `↑` `↓` `→`, or `D F J K`, Space also claps; on phones the pads are four big buttons and two thumbs can press a pair). Sung moves are notes on their pads: "step" alternates the feet, "left" and "right" in the waddle line take a foot each, flap · wings · flash · swim the flipper, clap and "bright" the clap pad, "hey" both feet and "crew" flipper and clap together, and every beat of the clap line is a clap. Notes snap to the half-beat grid. Fillers keep the beat where nothing is sung within three quarters of a beat: every beat in the choruses (left, clap, right, clap), every other beat elsewhere (left, right).

A hit within 70 ms is PERFECT, 120 ms GREAT and 180 ms GOOD; pressing a pad while only other pads are due breaks the combo, and pressing when nothing is due is free. Every ten hits a penguin belly-slides in to join the crew, up to thirteen, and the crew copies each hit move; a missed note makes one of them slip on the ice. From "Freeze" to "sway" nothing falls and any press counts as moving (holding still is worth 1000 points); "Stop when tired" is a rest with no notes, and the lyric-free dance break is fever time, where every press scores and spins the lead. The song plays once; misses, wrong pads and moving on Freeze drain the life gauge. `?start`, `?play` and `?auto` behave as in the other games, and the offset key is `penguin-game-offset`.


## Matter Run · States of Matter

The race uses a perspective camera behind the character, looking down a runway lined with modelled laboratory equipment. It starts at 36 units per second. Each cleared gate adds speed, with a larger increase as the combo grows, up to 52. Every miss removes 6 speed and resets the combo. At the 16-unit floor the run ends. The speed bar shows the remaining reserve; a fresh run starts at 36 again.

Speed drives the whole presentation: the chase camera lowers and moves closer, its lens widens, two tapered streams lengthen behind the character, more particles stretch into a wake, and up to 84 long world-space speed lines stream past. A subtle radial effect reinforces motion at the screen edges while leaving the character and central path sharp. Captions and controls remain outside the scene effect. Reduced-motion preferences suppress the extra camera movement, ribbons, radial effect and speed lines. The camera responds to actual current speed, so a miss also visibly releases the rush.

Music always plays at 1×, and English lyrics and action judgements follow its original timeline. Running speed is independent: track distance integrates combo acceleration and miss slowdowns while the camera, trail and speed lines follow the current running speed. Each gate locks its approach speed when it enters the 76-unit sightline; newly appearing gates use the current speed. This keeps visible gates from jumping during a slowdown and preserves every contact on its original musical beat. Slower approaches provide more preview time. Passed gates use a compressed departure path to preserve the late input window without clipping through the closer chase camera.

The four circular controls contain live 3D portraits rendered in one shared transparent canvas: bevelled ice with inclusions, a refractive curved drop, a continuous cloud surface and a moving plasma core. The characters have glossy eyes, cheeks and blinking expressions. A colored rim marks the active form, and a filling outer ring identifies the next gate. Only a short name and keycap remain visible. The title has its own floating element garden: frost, ripples, clouds or plasma orbits surround the selected character. The launch toy changes shape and material with the selection, which is preserved when starting or replaying. Pause and results are full-screen game overlays, without enclosing cards. Language and sound share the top-right row, with pause replacing language during active play. The lobby portraits stay centered; during play the form controls move left and a separate action button sits on the right. Portrait phones use a two-by-two form grid for the left thumb. Only the host's top-left back control is shown, without a duplicate bottom exit.

Large sing-along captions use bundled Nunito (SIL Open Font License, included under `src/matter/assets`). The current word lights up, while state and transformation vocabulary keeps its element color. Captions remain English-only in both UI languages. Caption visibility follows aligned word endings so a short source cue cannot hide the final teaching word. The font comes from [Google Fonts' Nunito sources](https://github.com/google/fonts/tree/main/ofl/nunito) and requires no remote font request.

Cover instructions occupy the existing blank space between the launch caption and the four characters. They are positioned independently, so adding them does not move the title, character stage, launch button or form controls. Compact screens use a shorter layout. The former top-center section, practice and upcoming-gate tutorial block is hidden during play.

A 3D transformation runner set in a sunlit floating particle laboratory, using the published **States of Matter** audio (about two minutes). Soft cloud islands, a pastel sky and pearl-colored equipment carry through the lobby, run and pause overlays. Open `#/stem-institute/states-of-matter/play`, or import `mountStatesOfMatter` from the package. Choose a form with `A S D F` (or `1 2 3 4`) or the four left buttons, then press **Space** or the large right action button near each gate: ice smashes, water slides, vapor jumps and plasma discharges. Form selection alone never clears an obstacle. The action button changes its icon and name with the form and lights up during the timing window. The title screen lets players try each form before starting.

The chart uses the original song's detected beats and aligned lyrics in `src/matter/analysis.json`, linked from the catalog work's `game/analysis.json`. The spoken intro has three opening gates at 3.135, 5.759 and 8.545 seconds (water, water, ice), so play begins promptly without cutting the opening English lyric. All later vocal gates retain their original timing and form. The first verse introduces all four forms every four beats; the speed rules apply from the first gate. Gate spacing tightens to three beats after 31.95 seconds, then two after 60.15 seconds and stays there; later verses do not reduce the pace. Verses follow sung states and choruses alternate all four forms. Obstacles arrive at the player's light ring on their charted beat. An action must use the correct form and fall between 400 ms before and 280 ms after contact. Within 140 ms earns PERFECT, within 260 ms GREAT, and the remaining window earns PASS. Early actions animate immediately and score at contact; late actions score immediately. Each gate accepts one action, and repeated presses cannot upgrade that grade. A wrong action can be corrected by changing form and pressing again before the window closes; changing form alone does not repair it. Holding Space does not repeat actions.

Combos multiply score up to ×4, and current speed adds a further ×1–×3 multiplier. The speed multiplier is captured when the accepted action is pressed, so the acceleration earned from that gate applies to future gates. The score display shows the current speed bonus. The run fails at the speed floor and clears when the actual audio ends, on the shared result screen with a grade, pass rate, best combo and cleared-gate count; the speed bar is drawn as the shared life gauge. Only manual runs starting from the beginning can update the saved best score. Lyrics highlight with the vocals. The action press drives the motion: ice lunges, water squashes beneath a pipe, vapor jumps and plasma spins its orbiting particles with electrical trails; successful gates separate into sectors and release staggered shock rings, particles, a brief lens ripple, a camera push and a colored light pulse along the track. Every complete ring is an interactive charted gate; there is no separate set of decorative rings to pass without feedback. The shared audio context plays a bass impact, stereo rush and a material-specific tail for every clear, with a stronger PERFECT. Wrong forms produce a red collapsing ring and impact sound. A fatal collision plays out for 650 ms under the FAILED stamp before the result overlay appears. Offscreen multisample antialiasing and environment reflections keep model contours and materials clear.

`start`, `play`, `auto`, `audio`, `lang`, `search` and `backHref` options follow the other mounts. `?auto&play` runs a demonstration; `?start=31` begins near the first chorus. Pause with `Esc`, `P`, the pause button or browser back; resume with the visible button. Backgrounding the page pauses it. Phones support portrait and landscape with large touch controls. `[` and `]` adjust sync, stored as `matter-game-offset`. Audio load failures have a retry action and rejected autoplay offers a click to resume. `destroy()` releases audio, listeners, wake locks, GPU objects and the canvas. The mount exposes `tally()`, `chart()`, `choose(index)` and `act()` alongside `destroy()` for hosts and interactive previews.

## Polygon Party

A one-button drawing game on the video's party stage, charted from `src/polygon/analysis.json` (linked from `aigc/songs/music/stem-institute/en-us/polygon-party/game/analysis.json`; its lyric timings carry the corrected alignment recorded in `lyric_alignment`). The ten polygons from the video stand in a ring on the raised circular stage, each on its own mark and facing outward; they never turn. It gets harder as the song goes (`LEVELS` and `chart` in `src/polygon/song.js`): from the 11.84 s drop the bar pattern is beats 1 and 3, then 1, 3 and 4 in the first chorus, 1, 2 and 3 in verse 2, every beat in the second chorus, every beat plus the off-beat after 4 in the bridge, every beat plus the off-beats after 1 and 3 in the final chorus, and every beat in the outro: 182 notes. The active polygon waits as a faint dashed outline; its own outline closes in from outside onto it before each note, over 2 beats at first, 1.5 from the second chorus and 1.25 in the final chorus. The next four notes close in at once, the next brightest and gold inside its window. A note lane under the stage (`src/polygon/lane.js`) shows the same notes plainly: they slide in from the right over beat lines (brighter on each bar) and are hit as they cross the target ring on the left, which shows the shape being drawn and turns gold on the note. Each note is the polygon it will draw, the one that completes a shape is bigger and gold-tipped, so the next shape's notes follow it in their own colour; a hit bursts on the target and a miss turns grey and slides on. Tap anywhere (or press Space, `J`, `F`, `K`, `D` or Enter) when it lands; on phones two drum pads (one wide pad in portrait) show the shape being drawn and light gold on the note, though the whole screen still counts: within 90 ms is PERFECT (300), within 220 ms GOOD (150), and the hit draws the next edge from corner to corner, lights the corner and its number, throws sparks from the tip and a shock wave in the polygon's shape. A tap outside the window but less than 0.6 s before the next note is EARLY and breaks the combo; other stray taps only tick. A note that passes unhit is a MISS: the combo breaks and the performer shudders red, but its drawn edges stay. The multiplier rises by one every 10 hits in a row, up to ×4. Closing a shape adds 500 × the multiplier, fills it, bursts it, sends a wave across the arena floor, punches the camera and lights its chip in the collection along the top; then the next polygon's turn begins, 3 to 12 and round again (a shape finished on an earlier lap is cleared when its turn comes back). Each chorus, the second verse and the bridge announce the change of pace. The game plays the song once from 6.5 s and clears at 127 s, after the last sung "landed!"; a MISS takes 10 of the life gauge and an EARLY 4, and the grade weighs GOOD as 0.6 of a PERFECT.

`src/polygon/camera.js`'s `ShotDirector` films the turn the way a music-show broadcast does, always from outside the ring. The active polygon gets a shot from in front of it: a slow push-in, a three-quarter angle, a low hero angle, a descending crane, an arc round it or a telephoto over the crowd's light sticks. A new subject gets a 0.66–1.15 s swing round the outside of the ring to its front, never across the stage: the pan leads, the dolly follows on a rising arc with a little roll, and the lens breathes. Each chorus and the outro open on the whole ring for 1.6 s, then cut to a new angle on every bar; hits punch the camera in and squeeze the lens, harder for a completed shape; a steadicam sway runs throughout. In the choruses and outro the rest of the ring hops and sways on the beat.

`src/polygon/stage.js` builds the stage (the plinth with pink, gold and cyan trim, a mirror ball, bunting looping round over the ring and falling confetti) and `src/polygon/venue.js` the arena round it: a ten-sided LED drum hung over the centre whose polygon tunnel, outline and equaliser follow the active side count and the beat, an LED band round the far walls, a ring of truss with twelve moving heads whose beams sweep the room, converge on each new subject for a beat and keep three follow spots on it, lasers fanning out from the drum in the choruses and outro, and a crowd all the way round whose light sticks wave together on the beat and who jump in the choruses. Fans at the lens, or close in front of it along where it looks, step out of the shot, and beams thin away near the lens, so neither washes out or blacks out the frame. The title screen's demo, and portrait screens, leave out the crowd and low shots and the wide chorus opening.

The name of the active polygon floats above it with a pip per edge, the verdict appears over it, and the lyric, with polygon names and numbers in their colours, sits at the bottom with the first notes' tip over it. `?start`, `?play` and `?auto` behave as in the other games, and the offset key is `polygon-game-offset`. The handle exposes `tally()`, `press()`, `audio`, `diagnostics()` (camera shot and pose, performers, beams) and `destroy()`.
