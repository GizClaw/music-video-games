# Contributing

## Setup

```sh
npm ci
npx playwright install chromium   # only for rendering videos
```

Rendering also needs `ffmpeg` and `uv`. Games need nothing beyond `npm ci`.

## Adding a song video

1. Use the song's AIGC catalog work path, e.g.
   `songs/music/stem-institute/en-us/<id>`. The directory
   `aigc/<work>/video/` must match it exactly, or the CLI will not find it.
2. Write `video/constants.js` with the section boundaries (on detected beats;
   `mvg-video --work <work> inspect` prints cues, beats and energy) and
   `video/song.js` exporting `createSong(ctx)`. Import shared code from
   `@gizclaw/mvg-core/…`.
3. Keep every scene a pure function of time: no state carried between frames,
   no unseeded randomness. Segments render in parallel.
4. Review with `mvg-video snap`, keep `mvg-video clearance` clear, then render.

See [packages/video/README.md](packages/video/README.md) for the analysis, lyric and rendering contracts.

## Adding a game

1. Write the game in `packages/games/src/` as a `mount<Name>(target, options)`
   export (see `mountBinaryBoogie`), using the shared pieces in
   `@gizclaw/mvg-games/kit.js`, `sfx.js` and `mobile.js`. There are no
   per-game pages: the universe mounts the game in place.
2. Create `aigc/<work>/game/`, write the trimmed beat data with
   `mvg-video --work <work> game-data`, move it into the package and leave
   `game/analysis.json` as a link to it.
3. Give the work a `WORK_EXTRA` entry in `site/catalog.js` with a `game`
   loader and `howto` so its planet lights up in the universe. New catalog
   albums or songs appear after `npm run universe:catalog`.
4. Play it through with `npm run dev` and `npm run play -- <work>`, then check
   `npm run build`.

See [packages/games/README.md](packages/games/README.md).

## Pull requests

Run `npm run check` and `npm run check:packages` before pushing; CI runs them with the Pages build. Label the
PR by area (`video`, `song`, `game`, `core`, `pages`, `ci`). Merges are
squash-only, and every merge to `main` redeploys the GitHub Pages site.

For a package change, bump that workspace's `package.json.version` and update
internal dependency pins and `package-lock.json`. Release tags are UTC snapshots
generated by the manual `release` workflow; package versions remain independent.
Released package versions are immutable: a content change requires a new version.

Song audio, lyrics and rendered videos are not committed. They belong to the
AIGC catalog and are read from, and written to, the mounted catalog root. The
README's preview images and GIFs are stored in Git LFS (`.gitattributes` routes
every image and video extension there), so install `git lfs` before adding one.
